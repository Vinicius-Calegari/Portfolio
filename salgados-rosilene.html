Salgados Rosilene.

Sistema de encomendas criado para substituir controles manuais por um fluxo único de catálogo, pedido, pagamento, agenda e operação administrativa. O frontend usa React/TypeScript e as regras críticas ficam no Supabase, com Postgres, Auth, Storage, RLS e Edge Functions.

Problema

Operação fragmentada

Pedidos, valores, clientes, agenda e cobranças precisavam coexistir sem depender de anotações paralelas.

Decisão

Regra no servidor

O navegador coleta a intenção; o backend recalcula preços, valida datas, limites, crédito e persistência.

Produção

Deploy verificável

GitHub Actions executa type-check, testes e build. A aplicação roda no Railway conectada ao Supabase.

Arquitetura

Cliente / Admin ↓ React + TypeScript + Vite ↓ Supabase JS ↓ Edge Functions ──→ validações / cálculo / pedidos ↓ PostgreSQL + RLS + Auth + Storage ↓ Railway (frontend em produção)

  • Preço recalculado e congelado no servidor no momento do pedido.
  • Pedido para o mesmo dia permitido quando ainda existe horário futuro disponível — sem exigência fixa de 3 dias.
  • Validação de datas bloqueadas, capacidade diária e antecedência máxima.
  • Fluxo de fiado condicionado à autorização do cliente.
  • Mensagens de WhatsApp preparadas para revisão e envio humano.

Compatibilidade e robustez

O bundle mira Chrome, Edge, Firefox e Safari, incluindo iPhone/iPad. Foram adicionados fallbacks para UUID, Clipboard, manipulação de imagens e modais para reduzir dependência de APIs exclusivas de navegadores Chromium recentes.

O CI da branch executa TypeScript, testes e build em Linux antes da publicação. O deploy usa variáveis públicas do Supabase configuradas na infraestrutura, mantendo credenciais privadas fora do GitHub.
